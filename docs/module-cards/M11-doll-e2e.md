# 模块卡片：M11 棉花娃娃端到端

- **目标**：实现 `examples/llm-doll-trade`——用全部已完成模块跑通协议文档 §9 阶段E 的 11 步闭环。这是项目的最终验收演示。
- **输入**：M6、M7、M8、M9、M10 全部验收通过；协议文档 §9 阶段E；技术选型 V0.4 §13。

## 输出

`examples/llm-doll-trade/`：

```text
├── README.md              # 演示剧本（11 步逐步对照）
├── run-demo.sh            # 一键演示（本地 GreenMail + 本地 tracker + 双索引器）
├── seller/                # 卖方模型配置与目录（棉花娃娃套装）
├── buyer/                 # 买方模型配置
└── assertions.mjs         # 逐步断言脚本
```

11 步（协议文档 §9E 原文）：卖方发布目录 → 整合商专题目录 → 检索站收录 → 买方找到并联系 → 议价 → 双签合同 → 钱包/人类支付 → 人类生产验货发货 → 物流签收事件 → 双方签名评价广播 → 至少一个独立整合商收录。

允许简化：支付用 `manual-settlement`（人类确认）或 `test-voucher`；人类步骤用 M7 任务 + 人工标记完成；整合商可用第二个索引器实例扮演（不同权重配置）。

## 验收指标

1. `run-demo.sh` 从干净状态跑完全部 11 步，`assertions.mjs` 每步断言通过（合同双签 valid、事件链到 `COMPLETED`、双方回执被两个索引器以不同权重收录、静态导出可离线查询）。
2. 演示中卖方与 BT tracker 中途下线后，买方仍能经索引站 HTTP 镜像取得目录（验证 2.4 存档角色）。
3. README 逐步对照协议文档 §9E，每步给出实际产生的 object_id/文件路径。

## 边界

- 不开发众筹平台；首轮可为预售口径但在 DEAL 内表达，不加新对象类型。
- 演示数据全部虚构；真实秘密禁止出现。
